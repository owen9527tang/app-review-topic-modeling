# 算法对照：NMF vs LDA

> 目的：回答「为什么用 NMF 而不是 LDA」。只换分解算法，其他全部不动——同一批 jieba 分词与停用词表、同一 TF-IDF 矩阵（min_df=5, max_df=0.5, sublinear_tf）、k=10、random_state=42。

样本 1681 条，词表 742 个词。LDA 同样拟合在 TF-IDF 上（而非词频矩阵），以便把差异归因于算法本身；代价是偏离 LDA 的多项式生成假设，这个偏离要在方法部分说明。

## 1. 一句话结论

换算法不推翻主要结论，但会改变「主题颗粒度」：7/10 个主题方向同号，可一一对应的主题只有少数几个。选 NMF 的理由是可解释性，不是它更「准」。

- **主题内部一致性**：NMF 平均 UMass = -2.58，LDA = -2.67（越接近 0 越好）；5/10 个主题 NMF 更连贯。差距不大，不足以单凭这一点选型。
- **主题可对应性**：匈牙利一一指派后，只有 2/10 个 NMF 主题能找到余弦 ≥ 0.6 的 LDA 对应主题（余弦中位数 0.43）。LDA 在 TF-IDF 上给出的主题更泛化、词更散，与 NMF 的细分主题（活动/付费/故障/客服）无法一一对上。**这是选 NMF 的实际理由：颗粒度更细、更好命名。**
- **结论复现**：7/10 个主题的「1 星 − 5 星」份额差在 LDA 下同号；医生合并主题 NMF -0.206 vs LDA -0.203，活动议题 NMF +0.220 vs LDA +0.032。LDA 下量级普遍更小，因为它把权重摊到更多主题上——这正是「原始差值含算法成分」的又一证据。
- **翻号的 3 个**：医院挂号与就医流程、客服售后与配送体检、患者获益与异地就医——正好是稳定性检验里边界或漂移的主题（`stability.md`），说明弱效应本身不可靠，而不是两个算法在打架。强效应（医生、活动、付费、App 功能、技术故障、免费咨询）方向全部一致。
- **稀疏性：不能作为选型理由**。两个指标方向相反——单条评论里份额 > 0.1 的主题数 NMF 2.15 vs LDA 1.52，份额归一化熵 NMF 0.39 vs LDA 0.65（1 = 完全摊平）。LDA 是「少数主题拿大头 + 一堆极小权重」，NMF 是「两三个主题各拿三成」，谁更稀疏取决于怎么定义。所以面试里不要说「NMF 更稀疏」，只说「NMF 的主题切得更细、能对上 codebook」。

## 3. 已补做与仍未做的对照

- **BERTopic / 嵌入类方法**：已补做，见 `outputs/bertopic_check.md`。本地 bge-small-zh-v1.5 → UMAP → HDBSCAN，自动得到 33 个簇、26.7% 噪声；「两端对应不同语义簇」与「技术故障簇以 2–4 星为主」都复现了。但与 NMF 的 10 个主题不是一一映射，不能做主题级数值对比。
- **LDA 拟合在词频而非 TF-IDF**：会影响与本文的可比性，未做。
- **人工主题命名的一致性**：10 个主题由单人命名，没有第二人复核（κ 未计算）。

## 4. 怎么在面试里用

被问「凭什么选 NMF」时，按这个顺序答：
1. 结论层面：换 LDA 后 7/10 个主题方向不变，医生合并主题方向也不变——所以选型不影响结论。
2. 方法层面：NMF 的 10 个主题能一一映射到 codebook（活动/付费/故障/客服…），LDA 的主题更泛化，命名不到这一层，也就无法向产品团队说清「该修哪里」。
3. 诚实层面：没做第二人编码（κ 未知）、LDA 用的是 TF-IDF 而非词频矩阵；这两条是明确的 next step。
