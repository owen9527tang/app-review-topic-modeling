# Codebook v0.2：互联网医疗 App 评论编码

> v0.2 变更（基于 50 条试点）：`other` 拆为 客服/活动营销/商品实物/内容推送；新增 `empty_praise` 标记；删除 `referral_mention`（试点 50 条仅命中 1 条）；`ai_context` 新增 `competitor_compare`。

## 0. 编码单位
一条评论 = 标题 + 正文。星级只作为上下文，不作为标签依据。

## 1. 基本原则
- 只编码评论中**明确出现**的内容，不推断。
- 同一条评论可以同时有 `complaint_themes` 和 `praise_themes`。
- 只提主题、没有评价（如“我在京东买药”）→ 不编码为抱怨或表扬。
- 泛泛的“垃圾/差评/骗子”但没有具体对象 → `complaint_themes=["other"]`，`overall_sentiment=-1`。
- 广告、刷评、无意义文本 → 两个主题列表都为空，`overall_sentiment=0`。
- **4 星的功能建议**（“如果能……会更方便”）→ 可编码 `complaint_themes`，但 `overall_sentiment=0`。
- **5 星但只有空泛好评**（“这软件太好了”“确实挺喜欢”）→ `praise_themes=[]`，`empty_praise=1`。

## 2. 主题（complaint / praise 共用）

| key | 名称 | 抱怨示例 | 表扬示例 |
|---|---|---|---|
| `fee` | 收费/退款 | 乱收费、退款不到账、自动扣费、药太贵、问诊次数受限 | 价格透明、退款快、性价比高 |
| `doctor` | 医生质量/响应 | 医生不回复、敷衍、态度差、不专业、偏袒医生 | 医生专业、回复快、解释清楚 |
| `delivery` | 药品配送 | 发货慢、送错药、物流不更新、包装破损 | 送药快、配送准时 |
| `prescription` | 处方/用药 | 处方不通过、开错药、剂量不对、副作用 | 用药指导清楚、处方审核快 |
| `appointment` | 预约/挂号 | 挂不上号、号源虚假、预约被取消、候诊太久、抢号加验证 | 挂号方便、预约顺利、复诊提醒 |
| `tech` | 技术/账号 | 闪退、卡顿、登录失败、验证码收不到、支付失败、功能被砍、设备连不上 | 版本流畅、操作简单、界面美观 |
| `privacy` | 隐私/安全 | 信息泄露、骚扰电话、强制实名、授权过多 | 隐私保护清楚、安全可靠 |
| `service` | 客服/售后 | 客服不回复、踢皮球、态度差、无投诉渠道 | 客服响应快、问题处理到位 |
| `promotion` | 活动/营销 | 活动虚假、提现失败、返现不到账、拉新奖励不兑现、商业化过重 | 活动实惠、补贴划算、打卡有用 |
| `goods` | 商品/实物 | 商品质量差、赠品不发货、实物设备难用、体检权益缩水 | 商品质量好、赠品实用 |
| `content` | 内容/推送 | 广告软文、推送骚扰、内容审核不当、文章消失、立场争议 | 内容专业、科普有用 |
| `other` | 其他（兜底） | 仅当确实无法归入上述任一类时使用 | 同左 |

## 3. AI 标记
- `ai_mention`：0/1。出现 AI、人工智能、智能助手、智能医生、大模型、DeepSeek、ChatGPT、GPT、豆包、文心一言、通义千问、讯飞、智能问诊、AI问诊、AI医生、AI助手、智能客服，或“客服像机器人”这类比喻。
- `ai_context`：
  - `feature_use`：实际使用本 App 的 AI 功能（如“AI 问诊很方便”）
  - `feature_trust`：对本 App AI 的信任/不信任（如“AI 看病不靠谱”）
  - `feature_failure`：本 App 的 AI 功能出错（如“AI 识别不灵”“AI 开错药”）
  - `competitor_compare`：拿其他 AI 产品做对比（如“豆包从来不掉线”）
  - `metaphor`：只是修辞比喻，不是真 AI 功能（如“客服像机器人”）
  - `none`：未提及
- `ai_sentiment`：-1 负面，0 中性/混合，1 正面。评价对象是被提及的那个 AI 实体。

## 4. 空泛好评标记
- `empty_praise`：0/1。仅对 5 星评论判定：`praise_themes` 为空或只有泛泛夸奖时记 1；有具体表扬对象记 0。其余星级一律 0。

## 5. 整体情绪
- `overall_sentiment`：-1 负面，0 中性/混合/建议，1 正面。以评论的主导语气为准，不直接照抄星级。

## 6. 输出 JSON
```json
{
  "labels": [
    {
      "review_id": "123",
      "complaint_themes": ["fee", "doctor"],
      "praise_themes": [],
      "ai_mention": 0,
      "ai_context": "none",
      "ai_sentiment": 0,
      "empty_praise": 0,
      "overall_sentiment": -1,
      "evidence_quote": "退款一直不到账"
    }
  ]
}
```

## 7. 边界规则
- “医生回复慢，但很专业” → `complaint_themes=["doctor"]`，`praise_themes=["doctor"]`。
- “客服像机器人” → `complaint_themes=["service"]`，`ai_mention=1`，`ai_context="metaphor"`，`ai_sentiment=-1`。
- “AI 问诊很方便，但不敢信” → `ai_mention=1`，`ai_context="feature_trust"`，`ai_sentiment=0`。
- “药送得快，但医生不回复” → `complaint_themes=["doctor"]`，`praise_themes=["delivery"]`。
- “客服不理我，退款也不到” → `complaint_themes=["service","fee"]`。
- “打卡返现不到账” → `complaint_themes=["promotion"]`，不要同时记 `fee`，除非另提到收费金额。
- “买了体脂秤连不上” → `complaint_themes=["goods","tech"]`。
- “主页全是广告和软文” → `complaint_themes=["content"]`。
- “升级后把历史问诊藏了，就是想多赚钱” → `complaint_themes=["tech","promotion"]`。
- 纯情绪“垃圾”“差评” → `complaint_themes=["other"]`，`overall_sentiment=-1`。

## 8. 人工编码：100 条 × 2 人（可核实性 + 主议题）

用于核验「5 星更空泛」这一条，**只编码抽样评论**，不编码全量。
`scripts/19_make_coding_sheets.py` 从 200 条分层抽样中按星级等比例取 100 条，生成两份**互盲**表：

- `data/coding_A.csv`：你本人编码；
- `data/coding_B.csv`：交给第二人独立编码（同一批 100 条，行序已打乱、不含星级列）。

两表都不写星级，因为判定只看文字、不看星级。两人读同一份手册（含判例），但**不讨论具体条目、不看对方答案**。

### 8.1 `spec`（文本具体性）：按顺序做两个测试

**测试 1｜有对象吗？**
把情绪词、脏话、口号全部划掉，剩下的文字里还有没有一个**能指认的对象**（医生、客服、某个功能页、某笔钱、某个药）？

- 没有 → 记 **`0`**。例：「垃圾 赶紧下架吧 别坑人了」「这软件真不错，推荐」。
- 有 → 进入测试 2。

**测试 2｜正文里有具体数量吗？**
看有没有一个**能用数字核对**的量：金额、次数、时长、字数、条数、日期、版本号。

- 有 → 记 **`2`**。例：「打卡 40 多天，任务完不成还扣 150 元」「时长从 178 减到 175」「更新后闪退，点了三次都退」「买了 3 次都没发货」。
- 没有 → 记 **`1`**。例：「数据严重滞后，推荐的医生搜不到了」「客服态度差」「会员自动续费都是垃圾」「订单没有可退的地方」。

**两条硬性边界（第一轮就是在这里出的问题）：**
1. **医生姓名、药品名、功能名、科室名、手术名一律算 `1`，不算 `2`。** 它们可核对，但不是「量」。「为孙桂连主任点赞」「做了室带肥厚切除手术」都是 `1`。
2. **「多次」「几句话」「一堆」这类模糊量不算数量词**，仍记 `1`。必须是能指向具体数值的表达（「三次」「150 元」「40 多天」）。

一句话记法：**2 = 正文里有一个能算出来的数；1 = 只说了事，没给数；0 = 连说的是哪件事都指不出来。**

数量词清单（照这个判，别凭语感）：

| 算（→ 2） | 不算（→ 1） |
|---|---|
| 150 元、三次、40 多天、一个半小时、十多年、50 个 | 一个 App、一批用户、一种方式、多次、一堆、好几天 |

「一个 App」「一批用户」里的「一个/一批」是冠词用法，不是数量；「多次」「一堆」「好几天」是模糊量，都没法核对。

### 8.2 `primary`（主议题，6 组单选）

**判定方法：这条评论如果要开工单，该派给谁？**

| 组 | 包含的细项 | 派给谁 |
|---|---|---|
| 医疗服务 | 医生质量、预约挂号、处方用药 | 医生端 / 问诊运营 |
| 费用与权益 | 收费退款、活动营销、客服售后 | 财务 / 客服 |
| 技术与账号 | 技术故障、隐私安全 | 技术 |
| 药品与商品 | 药品配送、商品实物 | 仓储物流 |
| 内容 | 内容推送 | 内容运营 |
| 其他 | — | 谁都派不出去 |

规则：
1. 先定组，再（可选）填细项；报告只按 6 组算 κ。
2. 一件事涉及两组时（「退款没到，客服也不回」），派给**用户最想解决的那一步**——钱没到 → 费用与权益。
3. 通篇没有可指认对象 → `其他`。「其他」不是不确定时的垃圾桶，是**确实没有议题**时才用。

真实判例：
- 「玩了 40 多天活动，任务不给过还扣 150 元」→ 费用与权益（活动营销）。
- 「去医院看病诱导注册，之后接到莆田医院推销，注销还非要打电话」→ 技术与账号（隐私安全）。
- 「推荐的医生通过医院小程序都搜不到了」→ 医疗服务（医生质量）。
- 「自动续费会员的都是垃圾」→ 费用与权益（收费退款）。
- 「垃圾 赶紧下架」→ 其他。

### 8.3 一致性口径与分歧处理
- 两名编码者**各自独立**完成（A 填 `coding_A.csv`，B 填 `coding_B.csv`）。两人都读本手册（含上面的判例），但**不得就具体条目互相讨论**，也不得看对方的答案。
- 具体性用**二次加权 Cohen's κ**（三值有序），主议题用 6 组普通 κ。
- 参考区间：<0.20 差，0.21–0.40 一般，0.41–0.60 中等，0.61–0.80 好，>0.80 很好。
- **低于 0.6 时不许硬报数字**：先按本节测试修手册边界，再重编；仍不达标就只报一致率与分歧条数。
- 有第三人时，第三人的角色是**裁决分歧条目**，不是再算一次 κ。裁决只看本节两个测试，不引入新标准。

**第一轮实测（2026-10，旧版手册）**：100 条，具体性加权 κ = 0.133、主议题（12 类）κ = 0.068。
诊断：两人对文本的判定都与长度相关（Spearman 0.485 / 0.415），说明都读了文字；分歧集中在 0/1 判定线与 12 类过细。
本节即据此改写：`spec` 由「能核对」进一步收紧为「正文有数量词」，`primary` 由 12 类合并为 6 组。

**第二轮自检（同一编码者，仅 A）**：按「是否含数量词」复核 A 判 2 的 61 条，其中 35 条正文无任何数量词
（多为「说了几句话」「订单没有可退的地方」这类只描述不计量），已改判 1；另有 4 条含数字却被判 1
（「挂了一个半小时」「50 个喝彩任务」等），已改判 2。收紧后 `2` 占 30%，与机械基线（含数字即算 2）的 32.1% 接近。
这说明 61% 是判定线偏宽造成的，不是文本本身有那么多数值细节。

**第二轮结果（A 按新手册重编、B 按新规则换算）**：`spec` 三分加权 κ = 0.271，换算后 0.387（该值因 `2` 由规则统一而偏高），
「有对象 vs 空泛」二元 κ = **0.164**；主议题 6 组 κ = 0.173。三者均无一起过 0.6。

**结论：本节规则未通过信度检验，人工标签不采用。**「5 星更空泛」继续用代理指标；本节仅保留特征口径 ——
`spec` 中真正可机械化的是「正文是否含数量词」（A 判 2 的 30 条里 29 条含数量词），该特征已改为规则生成，
不再依赖人工判断。详见 `outputs/coding_check.md` 第 6 节。

### 8.4 机检
`scripts/18_manual_check.py` 读取两份盲表、计算机械基线与 κ，输出 `outputs/coding_check.md`。

### 8.5 编码工具
`scripts/20_make_coding_tool.py` 把两份表打包成离线 HTML（`data/coding_tool_A.html` / `_B.html`）：
一条一条显示评论，点选 `spec` 与 `primary`，进度存在浏览器 localStorage，点「导出 CSV」得到可直接覆盖原表的文件。
工具**不显示星级、不显示机械基线判定、不显示字数** —— 任何一条都会成为编码锚点。
